01 / Overview

Project Overview

Developed a five-stage pipelined CPU with integer and floating-point register files, an ALU, an FPU datapath, multiply/MAC operations, and CSR-related logic. The project focused on pipeline correctness, efficient hardware utilization, and timing-aware RTL design.

Scope: graduate-level Advanced VLSI System Design coursework. This page summarizes a submitted technical report; it does not publish the course's proprietary testbench or supplied RTL.

02 / Architecture

Five Pipeline Stages

Instructions progress through instruction fetch, decode, execution, memory access, and write-back stages separated by pipeline registers.

IFInstruction Fetch

Conceptual pipeline diagram — simplified from the project's full datapath.

Fetch & Decode

The fetch stage selects sequential, predicted branch, or jump target addresses. Decode generates controls, immediate values, register operands, and stall requests.

Execute & Memory

Execution handles integer/floating-point operations and branch resolution. The memory stage supports byte, halfword, and word accesses with appropriate masking and extension.

03 / Design Highlights

Hazards, Prediction & Optimization

Data hazards

Forwarding & Stall Control

EX-stage forwarding prioritizes EX/MEM over MEM/WB data. WB-to-ID bypass reduces register read conflicts. Load-use dependencies that need data in EX incur a one-cycle stall.

Store dependencies

Load-to-Store Forwarding

Added WB-to-MEM forwarding for store data. A load followed by a store dependent only on the stored data can avoid a bubble; an address dependency still requires a stall.

Control hazards

Static Branch Prediction

Backward conditional branches are predicted taken and forward branches not taken. Actual outcomes are checked in EX, with PC correction and pipeline flushing on a misprediction.

Area reduction

Pipeline & Resource Sharing

Collapsed redundant pipeline result paths, shared the multiplier and ALU adder for MAC operations, and replaced separate FPU alignment paths with a shared shifter.

Timing closure

Fetch-Target Parallelism

Computed PC+4, branch targets, and JAL targets in parallel instead of placing immediate selection before a shared adder. A specialized fetch-target adder helped shorten the instruction-memory-to-PC path.

Datapath structure

FPU & Register File Logic

Used a logarithmic barrel-shift structure and hierarchical leading-zero detection. Reworked register-file reads using one-hot decode and a balanced OR reduction tree.

Engineering tradeoff: MAC resource sharing removed a third register-file read port and a dedicated MAC adder, at the cost of an extra preparation cycle for MAC instructions.

05 / Verification

Functional Checks & Timing

RTL & Gate-Level Simulation

All seven supplied programs (Prog 0–6) passed both RTL simulation and gate-level simulation according to the report.

Timing Reports

At a 1.335 ns synthesis clock period, reported worst setup slack was +0.0001 ns and worst hold slack was +0.0020 ns; both constraints were marked MET.

Superlint Reporting

The report lists 3,414 RTL lines, 91 warning lines, and 8 errors. Its reported 97.3% figure is calculated as 1 − (warning lines / total lines).

Interpreting Coverage

The 97.3% figure is a report-specific warning-line metric, not statement, branch, toggle, or functional verification coverage.
